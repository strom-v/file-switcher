# FileSwitcher — карта проекта

Читай этот файл в начале любой сессии в этом репозитории — он даёт быстрый контекст без необходимости заново исследовать код.

## Что это за программа и зачем

Настольное приложение для **macOS** (Electron + React + TypeScript), которое поднимает локальный HTTP/HTTPS-прокси на базе **mitmproxy** и подставляет системный прокси на все сетевые интерфейсы (Wi-Fi, VPN и т.д.). Пользователь задаёт правила «URL/regex → локальный файл» — и прокси на лету подменяет тело ответа сервера этим файлом, плюс может переопределять заголовки запроса/ответа, HTTP-статус и вносить задержку. Второе назначение — живой журнал (лог) всего проходящего HTTP(S)-трафика с поиском, фильтрами и просмотром деталей запроса (заголовки, тело).

Практическое применение: разработчик подменяет ответ бэкенда локальным файлом (например, версией фронтенд-бандла) без правки самого сервера, или наблюдает трафик приложения как в Fiddler/Charles.

## Архитектура (3 процесса)

```
Electron main (Node)  ──spawn──▶  mitmdump (Python, standalone binary)
       │                                │
       │ IPC                            │ -s addon.py  (аддон матчит правила, подменяет,
       ▼                                │              логирует трафик как JSON в stdout)
Electron renderer (React UI)            ▼
                                   rules.json (userData) — источник правил,
                                   addon.py перечитывает его по mtime вживую
```

- **[resources/addon.py](resources/addon.py)** — mitmproxy-аддон (`ResponseSwitcher`). Матчит `flow.request.pretty_url` против правил из `rules.json`, при совпадении подменяет `flow.response` содержимым локального файла (или только правит заголовки/статус/задержку, если `localFilePath` пуст). В `response()` логирует **каждый** прошедший запрос (не только совпавшие) как JSON-строку в stdout — включая `requestBody`/`responseBody` (декодированы как UTF-8 текст, `errors="replace"` для бинарных данных, **без лимита размера** — осознанный компромисс, см. «Известные ограничения»).
- **[src/main/proxyController.ts](src/main/proxyController.ts)** — спавнит `mitmdump` с `-s addon.py --set rules_file=<path>`, построчно парсит JSON из stdout, эмиттит `status`/`log`/`stderr` события.
- **[src/main/proxySystemConfig.ts](src/main/proxySystemConfig.ts)** — включает/выключает системный HTTP/HTTPS-прокси macOS (`networksetup -setwebproxy/-setsecurewebproxy`) на **всех активных network services**, включая VPN-профили, если те зарегистрированы как обычный service (проверено вживую — да, покрывает VPN). Сохраняет исходное состояние на диск для отката при падении.
- **[src/main/certInstaller.ts](src/main/certInstaller.ts)** — работа с CA-сертификатом mitmproxy (генерация происходит через `http://mitm.it`, этот модуль только устанавливает/убирает доверие в Keychain).
- **[src/main/rulesStore.ts](src/main/rulesStore.ts)** — персистит правила в `userData/rules.json`.
- **[src/main/ipc.ts](src/main/ipc.ts)** + **[src/preload/preload.ts](src/preload/preload.ts)** — весь IPC-контракт main↔renderer (`window.api.*`).
- **[src/renderer/App.tsx](src/renderer/App.tsx)** — корневой компонент: тулбар, сплиттер между панелью лога и панелью правил, Drawer с настройками.
- **[src/renderer/components/LogPanel.tsx](src/renderer/components/LogPanel.tsx)** — живой лог трафика: поиск по URL, фильтр «все / только сработавшие правила», фильтр по наличию тела запроса/ответа (кнопки ↑/↓, взаимоисключающие).
- **[src/renderer/components/LogDetailModal.tsx](src/renderer/components/LogDetailModal.tsx)** — детали одного запроса: заголовки, тело запроса/ответа (сырой текст + кнопка ручного JSON pretty-print).
- **[src/renderer/components/RulesTable.tsx](src/renderer/components/RulesTable.tsx)** + **[RuleFormModal.tsx](src/renderer/components/RuleFormModal.tsx)** — таблица правил (сгруппирована по репозиторию, извлечённому из `localFilePath`), редактирование/удаление через одну модалку (кнопка «удалить» — в футере модалки, не в таблице).
- **[src/shared/types.ts](src/shared/types.ts)** — общие типы для main/preload/renderer, включая формат `ProxyLogEvent` (ровно то, что шлёт `addon.py` в stdout).

## Сборка mitmdump

`mitmdump` — не npm-зависимость, а отдельный Python-инструмент, упакованный через PyInstaller в standalone-бинарник (`resources/bin/mac/mitmdump`), чтобы не требовать от пользователя установленного Python. Скрипты в `scripts/`: `setup_venv.sh` (создаёт `.venv`), `build_mitmdump.sh` (PyInstaller-сборка по `mitmdump.spec`), `mitmdump_entry.py` (entry-point для PyInstaller). В dev-режиме `proxyController.ts` использует `.venv/bin/mitmdump` напрямую, без пересборки.

`scripts/setup_sudoers.sh` — настраивает NOPASSWD-правило именно для `networksetup`, чтобы старт/стоп прокси не спрашивал пароль каждый раз (см. `proxySystemConfig.ts: installSudoersRule`).

## Что уже реализовано (актуально на 2026-08-28)

- Правила подмены: URL/regex-паттерн → локальный файл, с поддержкой `$1`/`$2` подстановки групп regex в путь. Плюс необязательные `contentType`, `requestHeaderOverrides`/`responseHeaderOverrides`, `delayMs`, `statusCodeOverride`. Кнопка «дублировать» в `RuleFormModal` (футер, рядом с «удалить») копирует все поля правила (включая продвинутые) в черновик без `id` — сохраняется как новое правило без заполнения формы с нуля. Клик по всей строке `RulesTable` (не отдельная иконка) открывает модалку редактирования — `onRow` на antd `Table`, клик по чекбоксу `enabled` не всплывает до строки.
- Автоматическое управление системным прокси при старте/остановке, с откатом при падении приложения (`recoverStaleSystemProxy`).
- Живой лог трафика с сохранением в буфер (лимит на категорию matched/passed, настраиваемый), поиском по URL/файлу подмены (опционально и по телу запроса/ответа — переключатель в тулбаре `LogPanel`), фильтрами, счётчиками (всего/matched, компактно иконка+число с tooltip) и экспортом (CSV/HAR, см. `csvExport.ts`/`harExport.ts`). Клик по всей строке лога (не отдельная иконка) открывает детали запроса.
- «Повторить запрос» в `LogDetailModal` — переотправляет запрос из лога напрямую на реальный сервер (не через локальный прокси — иначе рекурсия через `addon.py`), см. `src/main/replayRequest.ts` (IPC `proxy:replayRequest`). Скрыт для запросов с бинарным телом — тело в логе уже декодировано с `errors="replace"`, повторная отправка исказила бы байты.
- Тело запроса/ответа **всегда** логируется (без переключателя вкл/выкл — было упрощено по решению пользователя), доступно в деталях запроса и как фильтр списка. Бинарные тела (картинка, шрифт и т.п. — определяется строгой UTF-8-декодировкой в `addon.py`, поля `requestBodyIsBinary`/`responseBodyIsBinary`) в `LogDetailModal` показываются как пометка «бинарный файл, N байт» вместо нечитаемой строки с символами замены — кнопка форматирования JSON для них скрыта. Кнопка «форматировать» валидного JSON показывает сворачиваемое дерево (`JsonTree.tsx`, на antd `Tree`, подсветка по типу значения — вдохновлено jsonview из SBIS LOGS) вместо прежнего плоского текста с отступами. Пустое тело (запроса или ответа) секция вовсе не рендерит. Заголовки запроса/ответа в деталях свёрнуты по умолчанию (`Collapse`), блок тела крупнее блока заголовков (`.headers-panel--tall`, 220px против 100px).
- Настройки: тема (свет/тёмная), язык интерфейса (**ru / en**), размер шрифта, соотношение ширины панелей, лимит хранения лога, порт прокси, автозапуск (по умолчанию **включён** — если в `localStorage` ничего не сохранено, считается `true`, см. `useProxySettings.ts: readStoredAutoStart`).
- Кнопка запуска/остановки прокси — отдельная icon-кнопка в тулбаре рядом с кнопкой настроек (play/stop, цвет отражает статус); название приложения не кликабельно. Между настройками и play/stop — кнопка полного перезапуска приложения (`app:relaunch` IPC, `app.relaunch()` + `app.quit()` в main-процессе, проходит через существующий `before-quit`-хендлер, который останавливает прокси и откатывает системный прокси перед выходом), с подтверждением (`Popconfirm`); показывается только в production-сборке (`!import.meta.env.DEV`) — в dev-режиме electron-vite сам следит за пересборкой/HMR.
- Сертификаты: статус, установка/удаление доверия, список.
- Onboarding-модалка для первого запуска.

## Известные ограничения (не баги — осознанные технические границы)

1. **Перехват через forward-прокси, не прозрачный.** Работает только для приложений, которые сами читают системные macOS proxy-настройки (`CFNetwork`/`URLSession`, большинство GUI/Electron-приложений, браузеры). CLI-инструменты без явного чтения `http_proxy`/`https_proxy` (голый `curl`, некоторые скрипты) прокси не увидят.
2. **Полный прозрачный перехват (`mitmproxy --mode local`, бывший `osproxy`) недоступен** — требует подписанного и нотаризованного macOS Network Extension с Apple Developer ID, которого у проекта нет (`electron-builder.yml` собирает `identity: null`, неподписанная сборка). Обсуждалось и отклонено — см. `~/.claude/TASKLOG.md`, запись от 2026-08-27.
3. **`requestBody`/`responseBody` логируются без лимита размера** — осознанный выбор пользователя; риск раздувания памяти renderer на больших/бинарных телах (картинки, видео) остаётся.
4. `REVIEW.md` в корне — снимок code-review от 2026-08-24, частично устарел (пункт 1 там уже исправлен, остальные пункты не перепроверялись после — не считать его актуальным чек-листом без повторной проверки).

## Открытые задачи

- **Фильтрация лога по направлению трафика (исходящий/входящий), по образцу Fiddler.** Кнопки ↑/↓ в тулбаре [LogPanel.tsx](src/renderer/components/LogPanel.tsx) сейчас фильтруют по наличию непустого тела запроса/ответа — пользователь считает это не тем, что нужно («нам неважно есть тело или нет, нам важно ушёл этот запрос от нас или пришёл к нам»), но не смог сразу сформулировать альтернативу и попросил пока оставить как есть. Сложность: каждая запись лога — один HTTP-обмен (запрос+ответ вместе), не два раздельных события, поэтому прямое «исходящее/входящее» как фильтр записей не работает технически без другой единицы различия. Перед следующей правкой — уточнить у пользователя, что конкретно он имеет в виду под «как в Fiddler». Подробности решения не принимались — см. `[[log-traffic-direction-filter-todo]]` в project memory.

- ~~Race condition при быстром Stop сразу после Start~~ — **исправлено**: обработчики `spawn`/`error`/`exit` child-процесса теперь проверяют `this.child === child` (сравнение с конкретным инстансом, замкнутым в обработчике) перед тем, как трогать состояние контроллера — события от уже неактуального (заменённого повторным Start) процесса игнорируются. `stop()` обнуляет `this.child` немедленно, а не в отложенном `exit`-хендлере — иначе Start сразу после Stop видел бы `this.child` ещё не `null` и молча отказывался бы запускать новый процесс. Проверено вживую (`spawn`/`sleep`): второй `start()` после быстрого `stop()` не блокируется, отложенное `exit` от старого процесса корректно игнорируется.
- ~~`enableSystemProxy` молча ничего не делает, если нет активных сетевых сервисов~~ — **исправлено**: теперь бросает явную ошибку вместо тихого `return`; `proxyController.applySystemProxy` уже ловил такие ошибки в `catch` и показывал их пользователю через `stderr`-канал — правка использует существующий путь, ничего больше менять не пришлось.
- ~~`rulesStore.read()`/`write()` — молчаливая потеря правил при повреждённом JSON, запись не атомарна~~ — **исправлено**: `writeJsonFile` (`jsonFile.ts`) теперь пишет во временный файл рядом и делает `rename` поверх целевого (атомарно на POSIX — при падении посреди записи файл остаётся либо старым, либо новым целиком, никогда не наполовину записанным). `readJsonFile` получил опциональный `onCorrupted`-колбэк, вызываемый только при реальном повреждении файла (не при его отсутствии — это два разных, различаемых случая); `RulesStore` теперь `EventEmitter`, эмиттит `'corrupted'`, `ipc.ts` пробрасывает это через уже существующий `proxy:stderr`-канал — пользователь видит `message.warning` в UI вместо тихой потери правил, видимой только в консоли main-процесса. Проверено на реальной файловой системе: 4 сценария (запись+чтение, отсутствующий файл не триггерит corrupted, повреждённый — триггерит, fallback возвращается).
- ~~`execAsync` не различает ошибки, без таймаута — способна зависнуть на системном диалоге авторизации~~ — **частично исправлено**: `execAsync` теперь принимает `timeoutMs` (по умолчанию 10с), после истечения `execFile` убивает процесс `SIGTERM`. Единственное явное исключение — `runAsAdminViaOsascript` (диалог Touch ID/пароля) вызывается с `timeoutMs: 0` (без таймаута), потому что пользователь может думать над вводом произвольное время — это не зависание.
